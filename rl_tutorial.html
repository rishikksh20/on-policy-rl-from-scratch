Script 01 · PPO · deterministic verifier

PPO with an exact-match critic

The canonical on-policy actor–critic loop. One pretrained LFM backbone carries two heads: a tied language-model head for actions and a freshly initialized scalar head for values. A hard token-level verifier supplies the only task reward; GAE manufactures the critic's regression targets from that reward.

01_ppo_deterministic.py shared backbone GAE(γ, λ) clipped surrogate sampled KL penalty
In one sentence: sample an answer, score it 0 or 1, let a learned value function spread that score backwards over the tokens, then take a clipped policy step.
The algorithm, step by step

The math you can feel

∂Advantages and critic targets

TD residual δₜ = rₜ + γ·Vold(st+1) − Vold(sₜ)

GAE recursion Aₜ = δₜ + γλ·At+1

critic target Rₜ = Aₜ + Vold(sₜ)

At EOS the bootstrap is zero. If generation hits the token limit, the rollout is truncated and bootstrapped from the critic's value after the final token.

LClipped actor + value regression

importance ratio ρₜ(θ) = exp[ log πθ(aₜ|sₜ) − log πold(aₜ|sₜ) ]

actor Lactor = −𝔼[ min(ρₜAₜ, clip(ρₜ,1−ε,1+ε)Aₜ) ]

critic Lcritic = ½𝔼[(Vφ(sₜ) − Rₜ)²]

L = Lactor + 0.5·Lcritic

ε = 0.2, two epochs, gradient norm clipped at 1.0, one AdamW over both heads and the shared backbone.

1Rollout: sample, then re-score

sample_tokens runs the policy autoregressively with torch.multinomial. There is no KV cache — every step recomputes the full prefix. After sampling, positions_log_probs teacher-forces the same actions back through the model to recover log π_old(aₜ|sₜ) and the pre-action values. Everything is stored under no_grad.

Causal shift: feed prompt + actions[:-1]; read logits at indices P−1 … P+T−2. That is exactly the distribution each sampled action came from.

Code walkthrough
01

Recover per-token log probabilities with the causal shift

Gather the sampled action at each position. In tiny mode the softmax is restricted to the four allowed action IDs before gathering.

01_ppo_deterministic.py · positions_log_probs
ids = torch.tensor([prompt + actions[:-1]], dtype=torch.long, device=device)
logits, values = policy(ids, with_values=critic)
offset = len(prompt) - 1
selection = logits[:, offset:offset + len(actions), :].float()
if allowed_ids is not None:
    selection = selection[:, :, allowed_ids]
    mapped = [allowed_ids.index(a) for a in actions]
else:
    mapped = actions
act = torch.tensor(mapped, device=device).view(1, -1, 1)
logp = F.log_softmax(selection, dim=-1).gather(-1, act).squeeze(-1).squeeze(0)
val = values[:, offset:offset + len(actions)].squeeze(0) if critic else None
return logp, val
02

Backward recursion for advantages

next_v starts as the bootstrap scalar (zero at EOS) and then becomes the current value. next_a accumulates γλ.

01_ppo_deterministic.py · gae
ans = torch.zeros_like(rewards)
next_a = rewards.new_zeros(())
next_v = bootstrap
for t in range(len(rewards) - 1, -1, -1):
    delta = rewards[t] + gamma * next_v - old_values[t]
    next_a = delta + gamma * lam * next_a
    ans[t] = next_a
    next_v = old_values[t]
return ans, ans + old_values
03

Recompute, clip, regress, step

The old log-probs and returns are frozen tensors. Two epochs re-evaluate the current policy, so the ratio moves away from 1 and clipping engages.

01_ppo_deterministic.py · ppo_update
lp, values = positions_log_probs(actor, batch['prompt'], batch['actions'],
                                critic=True, allowed_ids=allowed)
ratio = (lp - batch['old_lp']).exp()
policy_loss = -torch.minimum(
    ratio * batch['advantages'],
    ratio.clamp(1 - clip_eps, 1 + clip_eps) * batch['advantages']).mean()
value_loss = .5 * (values - batch['returns']).square().mean()
loss = policy_loss + value_coef * value_loss
opt.zero_grad(set_to_none=True)
loss.backward()
nn.utils.clip_grad_norm_(actor.parameters(), 1.0)
opt.step()

!Gotchas

  • Strict verifier: exact token equality after stripping one trailing EOS. A numerically correct answer phrased differently still scores 0.
  • Tiny mode: random 3-layer model, 4-token action space, one generated token. It proves the loop, not the model.
  • Reference copy: copy.deepcopy(actor) doubles policy memory and is frozen with requires_grad_(False).
  • No KV cache: sampling re-runs the full prefix at every token — deliberately readable, deliberately slow.

Script 02 · PPO · learned preference reward

When nobody can write the answer key

Subjective tasks have no exact-match target. This script first trains a small scalar reward model on chosen vs rejected pairs, freezes it, and then runs the same PPO actor–critic loop — with the learned score replacing the deterministic verifier.

02_ppo_preference_reward.py pairwise preference data Bradley–Terry loss frozen reward backbone trainable scalar head
In one sentence: teach a scalar judge from human comparisons, freeze the judge, then let PPO chase its scores exactly as it chased the verifier in 01.
Builds on 01 · PPO — the actor–critic update is unchanged; only the reward source is new.
The algorithm, step by step
Who learns what · parameter dataflow

1Reward model architecture

The pretrained LFM backbone is deep-copied and frozen. Only a new scalar linear head trains. It reads the last hidden state of prompt + response.

score rψ(x, y) = wT · Backbone(x ⊕ y)last

The backbone's final output is already RMS-normalized; the head is a single linear layer. Freezing the backbone keeps the tutorial affordable — a production RM would often fine-tune it.

2Pairwise preference loss

Bradley–Terry probability P(y⁺ ≻ y⁻ | x) = σ( rψ(x,y⁺) − rψ(x,y⁻) )

negative log-likelihood LRM = −log σ( r⁺ − r⁻ )
      = softplus( r⁻ − r⁺ )

If chosen scores +2.0 and rejected scores −1.0, the loss is softplus(−3) ≈ 0.0486. The head is rewarded for widening the margin.

↻PPO stage in four moves

a

Sample fresh responses

The actor generates completions for prompt_ids from the preference dataset. Chosen/rejected strings are not replayed.

b

Freeze old π and reference π

Per-token log-probs and pre-action values are cached with no_grad; the reference copy supplies the KL penalty.

c

Score with the frozen RM

score = tanh(RM(prompt, actions)), bounded to [−1, 1], added at the final token.

d

Same clipped PPO update

Only the reward source changed. GAE, clipping, value regression and the optimizer are identical to script 01.

⚠Reward hacking & data hygiene

  • Do not train the RM on its own PPO outputs without fresh independent labels — that is a self-reinforcing score loop.
  • The pairwise rows train the head only. chosen_ids and rejected_ids are annotations, not PPO targets.
  • tanh keeps the toy reward bounded. A production RM needs calibration and held-out preference evaluation.
  • The backbone stays frozen through both stages, so only the scalar head and the actor/critic change.
Code walkthrough
01

The reward head sees the whole prompt + answer

The backbone runs under no_grad(); the final hidden state is detached before the trainable head. This is what makes the RM cheap to train and safe to freeze later.

02_ppo_preference_reward.py · LearnedReward
class LearnedReward(nn.Module):
    def __init__(self, pretrained_actor, c):
        super().__init__()
        self.backbone = copy.deepcopy(pretrained_actor.model).eval().requires_grad_(False)
        self.head = nn.Linear(c['dim'], 1).to(next(pretrained_actor.parameters()).device)

    def forward(self, prompt, response):
        ids = torch.tensor([prompt + response], device=next(self.head.parameters()).device)
        with torch.no_grad():
            last = self.backbone(ids)[:, -1].detach()
        return self.head(last).squeeze()
02

One softplus per pair, one optimizer for the head

After training, the RM is put in eval mode and every parameter is frozen. PPO then only reads scores from it.

02_ppo_preference_reward.py · train_reward_model
optimizer = torch.optim.AdamW(rm.head.parameters(), lr=lr)
for epoch in range(epochs):
    for record in records:
        p = record['prompt_ids']
        chosen = rm(p, record['chosen_ids'])
        rejected = rm(p, record['rejected_ids'])
        loss = F.softplus(rejected - chosen)
        optimizer.zero_grad(set_to_none=True)
        loss.backward()
        optimizer.step()
rm.eval().requires_grad_(False)
03

The only reward change: a scalar from the RM

The rest of the rollout is byte-for-byte the PPO recipe. The score lands on the final token; GAE spreads credit backwards.

02_ppo_preference_reward.py · rollout
actions = sample_tokens(actor, prompt, max_new=max_new, allowed_ids=allowed)
old_lp, old_v = positions_log_probs(actor, prompt, actions, critic=True, allowed_ids=allowed)
ref_lp, _ = positions_log_probs(reference, prompt, actions, allowed_ids=allowed)
score = torch.tanh(rm(prompt, actions)).item()   # bound [-1, 1] for toy stability
rewards = -beta * (old_lp - ref_lp)
rewards[-1] += score
# ... bootstrap, gae(rewards, old_v, boot), then ppo_update(...)

Script 03 · GRPO · no critic

Throw away the value network

GRPO keeps PPO's clipped importance-sampling objective but replaces the learned critic with a group baseline. Sample G responses to the same prompt, standardize their scalar rewards, and apply each resulting advantage to every token in that response.

03_grpo.py no value head group-relative advantage population std same KL leash G ≥ 2
In one sentence: if you sample several answers to the same question, the group's average score is a free baseline — so you can delete the critic entirely.
Builds on 01 · PPO — same clip, same KL, but the advantage comes from siblings instead of a value function.
The algorithm, step by step
Who learns what · parameter dataflow

μσGroup-relative advantage

μ = 1G Σᵢ rᵢ     σ = √( 1G Σᵢ (rᵢ − μ)² )

advantage for the whole response Aᵢ = ( rᵢ − μ ) / ( σ + 10⁻⁶ )

For rewards = [1, 0, 1, 0]: μ = 0.5, σ = 0.5, so A ≈ [+1, −1, +1, −1]. Better-than-average responses are pushed up; worse-than-average responses are pushed down.

LThe objective

importance ratio ρᵢₜ = exp[ log πθ(aᵢₜ|sᵢₜ) − log πold(aᵢₜ|sᵢₜ) ]

clipped policy term −1G Σᵢ 1|yᵢ| Σₜ min(ρᵢₜAᵢ, clip(ρᵢₜ,1−ε,1+ε)Aᵢ)

reference leash + β · D̂KL(πθ ‖ πref)

The KL estimator used in code is exp(d) − d − 1 with d = log π_ref − log π_θ, which is nonnegative.

Code walkthrough
01

Collect G trajectories and freeze their log-probs

Each rollout samples independently, stores the old policy and reference log-probs, and computes its scalar reward. Nothing is updated until the whole group exists.

03_grpo.py · group_rollout
for _ in range(group_size):
    actions = sample_tokens(actor, prompt, max_new=max_new, allowed_ids=allowed)
    old_lp, _ = positions_log_probs(actor, prompt, actions, allowed_ids=allowed)
    ref_lp, _ = positions_log_probs(reference, prompt, actions, allowed_ids=allowed)
    r = token_reward(actions, record['answer_ids'])
    out.append(dict(actions=actions, old_lp=old_lp.detach(),
                    ref_lp=ref_lp.detach(), reward=r))
r = torch.tensor([o['reward'] for o in out], device=out[0]['old_lp'].device)
std = r.std(unbiased=False)           # population std
advantage = (r - r.mean()) / (std + 1e-6)
02

Clipped policy loss + nonnegative KL

The advantage is a scalar per response and is broadcast over its tokens. The reference term keeps the actor from drifting too far.

03_grpo.py · grpo_update
new_lp, _ = positions_log_probs(actor, prompt, item['actions'], allowed_ids=allowed)
ratio = (new_lp - item['old_lp']).exp()
A = item['advantage']
p = -torch.minimum(ratio * A, ratio.clamp(1 - clip_eps, 1 + clip_eps) * A).mean()
log_ref_ratio = item['ref_lp'] - new_lp
kl = (log_ref_ratio.exp() - log_ref_ratio - 1).mean()
losses.append(p + beta * kl)
loss = torch.stack(losses).mean()
loss.backward()
nn.utils.clip_grad_norm_(actor.parameters(), 1.)
optimizer.step()

!Gotchas

  • All-equal group ⇒ Aᵢ = 0. If every sample passes or every sample fails, there is no outcome learning signal — only the KL term remains.
  • Population std (unbiased=False) is used, matching the G-division formula.
  • No critic saves a whole backbone, but variance reduction now depends entirely on the group.
  • Group size must be at least 2 in the preference variant; the base script defaults to 4.

Script 04 · RLVR · verifiable coding rewards

Rewards that can be checked, not guessed

RLVR is not a new optimizer. It is a discipline for defining rewards from objective evidence. Here the model writes an arithmetic expression, a safe AST interpreter runs it against unit tests, and the binary pass/fail becomes the GRPO reward.

04_rlvr_code_verifier.py binary unit-test reward AST whitelist GRPO update never exec() reward is sparse
In one sentence: replace the reward model with a tiny sandboxed interpreter — code earns 1 only if the whitelist accepts it and every unit test passes.
Builds on 03 · GRPO — the optimizer is identical; only the reward function becomes a verifier.
The algorithm, step by step
Who learns what · parameter dataflow

✓What counts as correct

verifier r(q, y) = 1  if code is allowed and passes every test
r(q, y) = 0  otherwise

The accepted grammar is deliberately tiny: a bare expression or def solve(a,b): return …, using only a, b, integer constants, + − * and parentheses.

Anything else — calls, imports, loops, comparisons, attributes — is rejected before evaluation.

!Why not just exec()?

Generated code is untrusted. Running it with exec() in the trainer process would be a remote-code-execution hole. The AST interpreter walks a whitelist and performs only integer arithmetic.

Real RLVR: use a separate sandbox or container, resource limits, timeouts and trusted tests. This educational verifier is intentionally incapable of arbitrary execution.

Code walkthrough
01

The whitelist interpreter

Each node type is handled explicitly. There is no fallback to Python evaluation: unsupported syntax raises ValueError.

04_rlvr_code_verifier.py · arithmetic
def arithmetic(node, a, b):
    if isinstance(node, ast.Expression):
        return arithmetic(node.body, a, b)
    if isinstance(node, ast.Name) and node.id in {'a', 'b'}:
        return a if node.id == 'a' else b
    if isinstance(node, ast.Constant) and type(node.value) is int:
        return node.value
    if isinstance(node, ast.UnaryOp) and isinstance(node.op, ast.USub):
        return -arithmetic(node.operand, a, b)
    if isinstance(node, ast.BinOp) and isinstance(node.op, (ast.Add, ast.Sub, ast.Mult)):
        left = arithmetic(node.left, a, b)
        right = arithmetic(node.right, a, b)
        if isinstance(node.op, ast.Add): return left + right
        if isinstance(node.op, ast.Sub): return left - right
        return left * right
    raise ValueError('Unsafe or unsupported generated program')
02

Normalize the answer format, then score all tests

Markdown fences are stripped; a single expression or a two-argument solve function is accepted. Any exception becomes a zero reward, never a crash.

04_rlvr_code_verifier.py · verify_unit_tests
def verify_unit_tests(code, tests):
    try:
        expr = extract_expression(code)
        return float(bool(tests) and all(
            arithmetic(expr, int(t['a']), int(t['b'])) == int(t['expected'])
            for t in tests))
    except (ValueError, SyntaxError, RecursionError, OverflowError, TypeError):
        return 0.0
03

Group sampling, verified rewards, GRPO

Tiny mode skips decoding entirely and maps four action IDs to toy expressions. Real mode uses the decoder built from tokenizer.json.

04_rlvr_code_verifier.py · verified_group
toy_map = {10: 'a+b', 11: 'a-b', 12: 'a*b', 13: 'a'}
for _ in range(group_size):
    actions = sample_tokens(actor, prompt, max_new=max_new, allowed_ids=allowed)
    logp, _ = positions_log_probs(actor, prompt, actions, allowed_ids=allowed)
    ref_lp, _ = positions_log_probs(reference, prompt, actions, allowed_ids=allowed)
    code = toy_map[actions[0]] if allowed is not None else decoder.decode(actions)
    reward = verify_unit_tests(code, record['tests'])
    group.append(dict(actions=actions, code=code, reward=reward,
                      old_lp=logp.detach(), ref_lp=ref_lp.detach()))
scores = torch.tensor([b['reward'] for b in group])
advantages = (scores - scores.mean()) / (scores.std(unbiased=False) + 1e-6)

!Gotchas

  • Tokenizer fidelity is part of the reward. A bad decode silently corrupts every score. Validate round-trips against the official tokenizer.
  • Binary all-or-nothing reward is very sparse. Random code rarely passes; curriculum and SFT initialization matter.
  • The decoder supports common ByteLevel/Metaspace models, not every possible decoder chain.
  • Equivalent code outside the whitelist (e.g. a if b else …) gets zero. The grammar is the spec.

In one sentence: same PPO math, but the critic owns its own pretrained backbone and optimizer — so actor gradients can never leak into the value function.
Contrast with 01 · PPO — identical reward and GAE, different parameter ownership.

value_loss = .5 * (values - batch['returns']).square().mean()
critic_opt.zero_grad(set_to_none=True)
(value_coef * value_loss).backward()
nn.utils.clip_grad_norm_(critic.parameters(), 1.0)
critic_opt.step()
03

Load the same checkpoint twice

initialize builds the actor and initialize_critic builds a critic with no LM head. Both load the official backbone; the scalar head stays freshly initialized.

05_ppo_independent_critic.py · main
actor, device = initialize(args.tiny, args.checkpoint)
critic, _ = initialize_critic(args.tiny, args.checkpoint, device=device)
reference = copy.deepcopy(actor).eval().requires_grad_(False)
actor_opt = torch.optim.AdamW(actor.parameters(), lr=args.lr)
critic_lr = args.lr if args.critic_lr is None else args.critic_lr
critic_opt = torch.optim.AdamW(critic.parameters(), lr=critic_lr)

!Gotchas

  • Memory: two pretrained backbones plus a frozen reference copy. Full FP32 230M training needs a serious device.
  • The critic's scalar head is newly initialized and is deliberately excluded from checkpoint strictness checks.
  • EOS uses zero bootstrap; truncation bootstraps from the independent critic's final value.
  • Separate learning rates are the point: --lr for the actor, --critic-lr for the critic.

The algorithm, step by step
Who learns what · parameter dataflow

RMReward model, reused

Identical architecture and training code to script 02: frozen LFM backbone plus a trainable scalar head, optimized with the pairwise Bradley–Terry loss and then frozen.

training LRM = softplus( rψ(x,y⁻) − rψ(x,y⁺) )

rollout reward rᵢ = rψ(x, yᵢ)   (raw scalar, no tanh)

Unlike script 02, GRPO standardizes the raw scores, so the absolute scale cancels out within a group — only relative ordering and spacing matter.

GGroup-relative advantages

μ = mean(r₁ … rG)    σ = population std

Aᵢ = ( rᵢ − μ ) / ( σ + 10⁻⁶ )

L = meanᵢ [ Lclip(Aᵢ) + β · D̂KL ]

Fresh completions are scored by the frozen RM. The chosen/rejected annotations are never replayed into the actor's rollouts.

02

Same GRPO loss as script 03

Only the reward source changed. The actor is the only optimized model during the RL loop.

06_grpo_preference_reward.py · grpo_update
new_lp, _ = positions_log_probs(actor, prompt, item['actions'], allowed_ids=allowed)
ratio = (new_lp - item['old_lp']).exp()
A = item['advantage']
p = -torch.minimum(ratio * A, ratio.clamp(1 - clip_eps, 1 + clip_eps) * A).mean()
log_ref_ratio = item['ref_lp'] - new_lp
kl = (log_ref_ratio.exp() - log_ref_ratio - 1).mean()
losses.append(p + beta * kl)
loss = torch.stack(losses).mean()
loss.backward()
optimizer.step()

Shared module · lfm.py

One small hybrid backbone

Every trainer imports the same model file. It reconstructs the LFM2.5-230M architecture in plain PyTorch: 14 layers that alternate short convolutions and grouped-query attention. The point is simple — local mixing for cheap patterns, global attention for long-range links.

The three ideas that matter

1Short convolution

A depthwise causal convolution with kernel 3 and double gating. It mixes only nearby tokens, so it is cheap and good at local syntax and arithmetic patterns.

b, g, z = chunk(in_proj(x), 3)
y = conv(b ⊙ z, k=3)
out = out_proj(g ⊙ y)

2Grouped-query attention

Global mixing with 16 query heads sharing 8 key/value heads. Q and K get RMSNorm and rotary positions. This is the only place a token can look far back.

q,k,v = projections(x)
q,k = RoPE(RMSNorm(q), RMSNorm(k))
out = SDPA(q, k, v, causal)

3Shared block parts

Both layer types wrap the operator in residual connections, RMSNorm and a SwiGLU feed-forward (1024 → 2560 → 1024). No biases anywhere.

x = x + operator(norm(x))
x = x + w2(silu(w1(norm(x))) ⊙ w3(norm(x)))

Weights load from the official BF16 safetensors file with a small standard-library reader. --tiny swaps this for a random 3-layer model (vocab 96, dim 32) so the trainers run offline on CPU. Never combine --tiny with the real checkpoint.

↦The two encode helpers

prompt_ids applies the chat template with a generation prompt. response_ids encodes the continuation without a second BOS and guarantees one trailing EOS.

prepare_data_optional.py
def prompt_ids(question):
    ids = tok.apply_chat_template(
        [{'role': 'user', 'content': question}],
        tokenize=True, add_generation_prompt=True,
    )
    return list(ids)

def response_ids(answer):
    ids = tok.encode(answer, add_special_tokens=False)
    if not ids or ids[-1] != tok.eos_token_id:
        ids.append(tok.eos_token_id)
    return ids

!Gotchas

  • Optional: this is the only Transformers dependency in the whole repo. Trainers run without it.
  • One EOS: the helper appends EOS only if missing. Duplicate EOS changes the verifier's cleaned match.
  • No decode in trainers: RLVR has a lightweight decoder, but encoding is always the official tokenizer's job.
  • Real tokenizer: LiquidAI/LFM2.5-230M; the chat template is applied exactly as above.
